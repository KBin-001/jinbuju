# 手动行动 MVP

## 当前主流程

```text
创建目标 -> 今日页 -> 添加行动 -> 状态与时间记录 -> 顺延 -> 行动进度
```

本分支使用微信本地 storage 跑通基础 MVP，不调用云函数、不写入线上数据库。

## 数据结构

- `Goal`：单个当前目标及历史状态。
- `ActionTask`：行动标题、原计划日期、当前日期、预计/实际时间、状态及问题原因。
- `DailyCheckin`：同一目标、同一业务日期的一条今日记录；重复记录会更新原记录。
- `ProgressSummary`：由 service 层根据行动数据实时计算，不单独持久化。

本地数据统一保存在版本化键 `JINBUJU_MANUAL_MVP_V1` 中。页面不直接修改数据结构。

## AI 与小队

原有 AI 页面、云函数、类型和 service 均保留。`miniprogram/config/features.ts` 中的
`ENABLE_AI_PLANNER` 和 `ENABLE_TEAM` 默认均为 `false`，当前主流程不展示入口，也不会触发调用。

后续恢复 AI 时，应先接回可信云函数和数据库，再在目标创建成功后的路由中显式增加分析/预览流程，完成联调后才开启 feature flag。

## 当前限制

- 本地数据不跨设备同步，也没有服务端身份校验。
- 业务日期暂按设备日期计算，接入云端后必须改用服务端 `Asia/Shanghai` 业务日期。
- 清除数据只清除此 MVP 的本地 storage，不删除任何线上数据。
