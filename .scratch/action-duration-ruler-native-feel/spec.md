# 添加行动预计投入时间尺：稳定吸附与原生触感优化

## Problem Statement

用户在“今日”页的添加行动半屏中左右滑动“预计投入”时间尺时，滚动明显卡顿，选中值与松手后的最终值不稳定；即使滑到 30 分钟，松手后也可能突然跳到 5 分钟。当前实现还会在每次跨过刻度时反复停止、归零并播放项目内置 WAV 音效，声音生硬且高频播放会进一步放大卡顿感。用户希望保留现有横向时间尺和整体 UI，只把手指跟随、惯性、停稳吸附与反馈质感优化到接近 iOS 原生时间滚轮的舒适程度。

## Solution

保留现有添加行动半屏、横向刻度尺、中央指示器、分钟数字、小时换算和 5～360 分钟业务范围，不重做视觉结构。将时间尺交互改为明确的“开始拖动 → 连续预览 → 惯性滚动 → 单次停稳吸附 → 提交选值”生命周期：滚动过程中只在跨过新的 5 分钟档位时更新预览值，不再持续反向写入滚动位置；惯性真正停止后才做一次最近档位吸附，并对程序触发的滚动进行隔离，防止旧事件或边界事件把值重置到 5 分钟。

移除当前刻度变化时播放的自制 WAV 音效。微信小程序没有公开 API 可以从自定义控件调用 iOS 闹钟或微信原生时间滚轮的系统刻度音；因此本次以 `wx.vibrateShort` 的 `light` 原生轻触感作为横向时间尺的反馈，并进行档位去重与频率限制。设备不支持、用户关闭相关反馈或调用失败时保持安静，不回退到当前难听的音频。这样能在不改变 UI 方向的前提下，获得更接近系统滚轮的“每跨一格有一次轻反馈”的感受。

## User Stories

1. As an 添加行动的用户, I want 时间尺紧跟手指移动, so that 我能自然控制预计投入时长。
2. As an 添加行动的用户, I want 松手后保留我看到的最近档位, so that 30 分钟不会突然跳回 5 分钟。
3. As an 添加行动的用户, I want 时间尺在松手后有平顺且可预测的惯性, so that 操作感接近 iOS 原生滚轮。
4. As an 添加行动的用户, I want 惯性结束后只发生一次短距离吸附, so that 时间尺不会来回回弹或二次跳动。
5. As an 添加行动的用户, I want 滚动过程中分钟数字同步变化, so that 我随时知道中央指示器对应的时长。
6. As an 添加行动的用户, I want 小时换算与分钟数字同步变化, so that 长时行动仍容易理解。
7. As an 添加行动的用户, I want 每跨过一个有效档位获得一次轻反馈, so that 手指滑动时能感知档位切换。
8. As an iPhone 用户, I want 反馈使用系统支持的轻触感, so that 它不会像重复播放音频文件一样刺耳。
9. As an Android 用户, I want 不支持一致触感的设备也能稳定选值, so that 反馈差异不会影响核心操作。
10. As an 关闭反馈的用户, I want 时间尺保持静音且不振动, so that 产品尊重我的偏好。
11. As an 设备处于静音环境的用户, I want 时间尺不强制播放音频, so that 添加行动不会打扰周围的人。
12. As an 快速滑动的用户, I want 反馈有频率上限, so that 连续跨越多个档位时不会产生轰鸣或阻塞主线程。
13. As an 缓慢精调的用户, I want 每个 5 分钟档位都可稳定到达, so that 我能准确设置较短行动。
14. As an 添加行动的用户, I want 最小值稳定停在 5 分钟, so that 左侧边界不会越界或抖动。
15. As an 添加行动的用户, I want 最大值稳定停在 360 分钟, so that 右侧边界不会越界或抖动。
16. As an 添加行动的用户, I want 30、45、60、90、120 和 240 分钟继续可选, so that 常用预计投入不受优化影响。
17. As an 编辑已有行动的用户, I want 打开面板时准确定位到已保存时长, so that 编辑不会悄悄改变原值。
18. As an 编辑已有行动的用户, I want 不滑动时间尺也能原样保存, so that 初始化滚动事件不会修改任务数据。
19. As an 小屏设备用户, I want 时间尺换算不受视口宽度和像素密度影响, so that 同一位置在不同设备上得到同一档位。
20. As an 使用系统字体放大的用户, I want 数字、单位和刻度仍不遮挡操作区域, so that 可读性设置不会破坏时间选择。
21. As an 添加行动的用户, I want 现有标题、执行方式、重要程度、日期、提醒和保存流程保持不变, so that 本次优化不会扩大操作成本。
22. As an 维护者, I want 程序吸附事件与用户滚动事件可区分, so that 后续视觉调整不会再次引入跳值回归。
23. As an 维护者, I want 反馈失败不影响选值和保存, so that 触感属于渐进增强而不是核心依赖。
24. As an 维护者, I want 页面离开或弹层关闭时清理滚动定时器与反馈资源, so that 重复打开不会残留旧事件。

## Implementation Decisions

### 1. 保留现有信息结构和视觉语言

- 继续使用横向时间尺、中央选中指示器、分钟大数字、小时换算和现有山水风格半屏。
- 不改动“添加行动”其他字段、按钮层级、数据模型或保存契约。
- 业务范围继续为 5～360 分钟，选择精度继续为 5 分钟；现有稀疏可视刻度策略可以保留。
- 预计投入和实际投入仍是两个独立字段，本次只改变预计投入的交互层。

### 2. 用单一滚动生命周期管理预览与提交

- 时间尺建立明确的用户拖动状态、惯性滚动状态、停稳状态和程序吸附状态。
- 用户滚动事件只读取当前位置并计算最近的 5 分钟预览值；同一档位内的连续事件不重复更新页面数据。
- 滚动过程中禁止回写受控滚动位置，避免用户手势、原生惯性和程序动画竞争同一个属性。
- 采用停滚检测，在最后一次真实滚动事件后确认惯性结束，再只执行一次最近档位吸附。
- 程序吸附产生的后续滚动事件必须被标记并忽略或正确归并，不能再次启动旧的停滚任务。
- 新一轮手势开始时立即取消上一轮尚未执行的停滚吸附，防止旧定时器覆盖新手势。
- 首尾边界事件复用同一套钳制与提交逻辑，不再各自强制同时更新分钟值和滚动位置。

### 3. 使用增强滚动能力降低 iOS 惯性失控

- 继续启用增强滚动能力，并开启可提升滚动性能的 passive 特性。
- iOS 使用增强滚动的快速减速能力，缩短长距离惯性，提升刻度尺的可控性；Android 保持平台默认减速行为。
- 初次打开或载入已有行动时，在节点完成布局后无动画定位一次，随后才允许用户交互和反馈。
- 最终吸附可以使用一次克制的短动画，但初始化定位、边界纠正和程序状态同步不得产生连续动画链。

### 4. 降低跨线程更新量

- 分钟预览只在计算结果跨入新档位时更新，不能对每个原始滚动事件执行 `setData`。
- 小时文案与分钟值在同一次状态提交中更新。
- 反馈调用与视觉状态更新解耦；反馈失败不得重试、阻塞或回滚选值。
- 页面关闭、卸载和面板重开时清理停滚计时、程序吸附标记和本轮反馈状态。

### 5. 用原生轻触感替代自制刻度音

- 停止使用当前两段刻度 WAV 和高频 `stop → seek → play` 播放方式。
- 每次首次跨入新的 5 分钟档位时，可调用 `wx.vibrateShort({ type: "light" })`；同一档位只反馈一次。
- 反馈设置频率上限，建议相邻调用至少间隔 60～80ms；快速甩动时允许跳过中间反馈，优先保证滚动流畅。
- 初始化定位、程序吸附产生的回调、边界修正和打开已有行动时不触发反馈。
- 若既有本地“刻度反馈关闭”偏好为关闭，沿用该选择；若需要迁移设置名称，应兼容读取旧键，避免重新打扰已关闭反馈的用户。
- 不使用未公开接口、原生插件或伪装成系统音的未经授权音频。

### 6. 明确系统声音能力边界

- 微信公开的内部音频上下文要求开发者提供音频资源地址，只能播放应用自己的音频，不能选择 iOS 系统滚轮音。
- 微信原生 `picker-view` 官方说明在 iOS 滚动时自带系统触感反馈，但它是纵向滚轮组件，替换后会明显改变现有横向 UI，因此本次不采用。
- 如果未来产品必须获得完全一致的微信/iOS 纵向时间滚轮体验，应另立设计议题评估原生时间选择器；不能把这一能力伪装为本次横向时间尺的小改动。

### 7. 失败与兼容策略

- 触感 API 不可用、被系统限制或调用失败时静默降级为无反馈，时间尺仍须完整可用。
- 不因设备品牌、微信版本或触感能力改变分钟范围、步长、保存值或文案。
- 实机触感只作为渐进增强；开发者工具无法模拟时不得因此判定业务失败。

## Testing Decisions

### 什么算好测试

测试只断言用户可观察到的时间尺行为：给定一串开始拖动、滚动、惯性和停稳事件，预览值如何变化、最终值停在哪里、发生几次吸附、反馈是否去重和节流。测试不绑定具体定时器变量名、CSS 类名或事件处理函数拆分方式。

### 唯一测试 seam：预计投入时间尺交互控制器

将“滚动位置 ↔ 5 分钟档位换算、拖动生命周期、停稳吸附、边界钳制、程序事件隔离、反馈节流”作为一个可独立驱动的交互控制器测试。页面只负责把原生滚动事件送入控制器，并把控制器输出映射为分钟预览、滚动定位和触感调用。

该 seam 至少覆盖：

- 从 30 分钟开始，轻微滑动后停稳仍落在最近档位，而不是跳到 5 分钟。
- 滑到显示 30 分钟后松手，惯性和程序吸附事件序列最终仍提交 30 分钟。
- 快速连续滚动时只在跨档位时更新，停稳后只有一次吸附。
- 程序吸附产生的滚动事件不会开始第二轮吸附或覆盖最终值。
- 上一轮停滚任务在新手势开始时被取消。
- 5 分钟和 360 分钟边界可达且不会重复回弹。
- 30、45、60、90、120、240 分钟的滚动位置与选值双向换算一致。
- 不同窗口宽度下，相同逻辑刻度得到相同分钟值。
- 初始化和编辑态定位不产生触感，也不修改原有预计投入。
- 同一档位重复事件不触发重复反馈。
- 快速跨越多个档位时反馈满足频率上限。
- 反馈关闭、API 缺失或 API 失败时，最终选值与吸附行为完全一致。

### 既有先验与回归验证

- 复用现有添加行动半屏契约测试，继续保证横向滑动提示、刻度范围、执行方式、重要程度、日期、提醒、删除和保存入口存在。
- 复用现有行动服务测试，保证预计投入以整数分钟保存，且不与实际投入混用。
- 在微信开发者工具验证布局、滚动范围、保存闭环和无新增报错。
- 必须在至少一台真实 iPhone 和一台真实 Android 设备上验证慢拖、快速甩动、反向滑动、连续开关弹层和边界操作；触感品质不能只靠模拟器验收。

## Out of Scope

- 不重做添加行动半屏的视觉样式、卡片结构或字段顺序。
- 不把横向时间尺改成纵向 `picker-view` 或系统弹出式时间选择器。
- 不尝试调用不存在的 iOS 系统刻度声音接口。
- 不制作、购买或替换另一套自定义音频素材；本次目标是移除难听音效并使用原生轻触感。
- 不修改预计投入范围、任务数据模型、实际投入、专注计时、提醒授权或云端同步。
- 不顺带重构独立行动编辑页的按钮式时长选择器；如后续要求全项目统一交互，应另立议题。
- 不修改今日页其他卡片、日历、AI 教练、行动榜或底部导航。

## Further Notes

- 当前卡顿与跳值的主要风险来自：滚动过程中高频页面状态更新；最后一次滚动仅等待约 100ms 就带动画强制回写滚动位置；回写又会产生新的滚动事件；首尾事件还会独立强制改值。用户手势、原生惯性和程序动画因此可能互相覆盖。
- 当前声音并非微信原生声音，而是项目内两段 WAV；每次跨档位都会执行停止、归零和重新播放，既影响听感，也可能增加滚动热路径上的工作量。
- 微信官方 `scroll-view` 文档说明增强模式提供 passive、iOS 边界弹性、快速减速及拖动生命周期事件：https://developers.weixin.qq.com/miniprogram/dev/component/scroll-view.html
- 微信官方 `picker-view` 文档明确说明 iOS 滚动时带系统触感反馈，同时其交互形态为页面内纵向滚动选择器：https://developers.weixin.qq.com/miniprogram/dev/component/picker-view.html
- 微信官方 `wx.vibrateShort` 文档提供 15ms 短振动及 `light` 强度：https://developers.weixin.qq.com/miniprogram/dev/api/device/vibrate/wx.vibrateShort.html
- 微信官方 `InnerAudioContext` 文档只提供指定音频资源地址的播放能力，没有系统滚轮声音选择能力：https://developers.weixin.qq.com/miniprogram/dev/api/media/audio/InnerAudioContext.html
- 本规格已按“保留 UI、优先修复跳值、原生触感替代难听音效”的目标确定测试 seam，可直接进入实现；若未来接受改为纵向原生滚轮，再单独比较两种交互方向。
