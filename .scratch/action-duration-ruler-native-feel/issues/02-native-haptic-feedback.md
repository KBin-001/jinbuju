# 02 — 用原生轻触感替换自制刻度音

**What to build:** 在稳定的时间尺档位事件基础上，停止播放当前生硬的自制刻度音，改为每次首次跨入有效档位时提供克制的系统轻触感。快速滑动时反馈必须去重和节流，不支持触感、用户已关闭反馈或调用失败时保持安静，且任何反馈状态都不能影响预计投入的选值与保存。

**Blocked by:** 01 — 稳定时间尺拖动、惯性与停稳吸附.

**Status:** ready-for-agent

- [ ] 时间尺不再创建、停止、归零或播放现有的主次刻度 WAV 音频。
- [ ] 用户首次跨入新的 5 分钟档位时使用系统支持的 `light` 短触感，同一档位的重复滚动事件只反馈一次。
- [ ] 相邻反馈设置 60～80ms 的最小间隔；快速甩动时允许跳过中间反馈，滚动流畅度优先于逐格反馈完整度。
- [ ] 初始化定位、打开已有行动、程序吸附、边界修正和程序滚动回调不触发触感。
- [ ] 用户从一个档位滑回已经离开过的档位时可以获得新一轮轻反馈，但不得因程序回调产生重复反馈。
- [ ] 既有“刻度反馈关闭”本地偏好继续生效；如调整设置命名，兼容读取旧值，不重新为已关闭反馈的用户开启触感。
- [ ] 触感 API 不存在、设备不支持、系统限制或调用失败时静默降级，不播放自定义音频，也不重试或阻塞主线程。
- [ ] 反馈关闭、API 缺失和 API 失败时，时间尺的预览、吸附、最终选值及保存结果与正常设备完全一致。
- [ ] 面板关闭和页面卸载时清理本轮反馈档位与节流状态，不保留音频上下文或其他媒体资源。
- [ ] 测试覆盖档位去重、频率限制、初始化静默、程序吸附静默、偏好关闭和 API 失败降级。
- [ ] 项目调用关系确认旧刻度音无其他使用者后再清理对应资源，不删除仍被其他功能引用的资源。
- [ ] 至少在一台真实 iPhone 上验证慢拖逐格触感、快速甩动节流、静音环境和系统触感设置差异。
- [ ] 至少在一台真实 Android 设备上验证触感能力差异不会影响滚动、选值和保存，微信开发者工具中的无触感表现不视为失败。
- [ ] 完整添加行动流程可正常提交，预计投入与实际投入字段语义没有变化，业务数据和云端同步不受影响。
