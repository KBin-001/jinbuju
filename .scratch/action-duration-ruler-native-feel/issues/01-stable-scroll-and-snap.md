# 01 — 稳定时间尺拖动、惯性与停稳吸附

**What to build:** 在不改变添加行动半屏现有横向时间尺、视觉结构和业务范围的前提下，让预计投入时间尺形成稳定的“拖动预览—惯性滚动—单次停稳吸附—提交选值”闭环。用户滑到 30 分钟后松手必须稳定停在最近档位，不再跳回 5 分钟；初始化、编辑已有行动、边界操作和连续手势也必须保持可预测。

**Blocked by:** None — can start immediately.

**Status:** ready-for-agent

- [ ] 保留现有横向时间尺、中央指示器、分钟数字、小时换算和整体 UI，不调整添加行动其他字段或保存流程。
- [ ] 预计投入继续支持 5～360 分钟，选择精度为 5 分钟，并可准确到达 30、45、60、90、120 和 240 分钟等常用值。
- [ ] 用户滚动过程中只在跨入新的 5 分钟档位时更新分钟预览和小时文案，同一档位内的连续滚动事件不重复更新页面状态。
- [ ] 用户滚动和原生惯性期间不持续回写受控滚动位置，避免手势、惯性和程序动画竞争。
- [ ] 最后一次真实滚动结束后只执行一次最近档位吸附，程序吸附产生的滚动事件不会启动第二轮吸附或覆盖最终值。
- [ ] 新手势开始时取消上一轮尚未执行的停稳任务，快速反向滑动和连续滑动不会被旧事件覆盖。
- [ ] 从 30 分钟开始或滑到 30 分钟后松手，最终提交值保持在最近的 5 分钟档位，不能跳到 5 分钟。
- [ ] 5 分钟和 360 分钟边界复用统一钳制与提交逻辑，不产生重复回弹、越界或边界事件抢写。
- [ ] 打开新增面板时无动画定位到默认值；打开编辑面板时准确定位到已保存时长，初始化事件不会改变任务值。
- [ ] 增强滚动使用 passive 性能能力；iOS 使用适合短刻度尺的快速减速能力，Android 保持稳定的默认平台行为。
- [ ] 面板关闭、重新打开和页面卸载时清理停稳任务、程序吸附标记和本轮交互状态。
- [ ] 交互控制器测试覆盖拖动、惯性、停稳、程序事件隔离、连续手势、双边界、常用时长和不同窗口宽度的双向换算。
- [ ] 现有添加行动半屏契约测试继续通过，标题、执行方式、重要程度、日期、提醒、删除和保存入口没有回归。
- [ ] 在微信开发者工具完成慢拖、快速甩动、反向滑动、边界选择、编辑态定位和保存闭环验证，无新增编译错误或明显警告。
