# 全局字号规范化：以今日页阅读密度统一进度页与全项目排版

## Problem Statement

用户在四个主 Tab 之间切换时，能明显感到同一层级的文字忽大忽小。最突出的例子是进度页从“教练观察”开始：标题、结论、建议、趋势标题与后续记录区域的字号整体偏大，对比今日页更显拥挤和沉重，破坏了产品轻量、安静、年轻的阅读节奏。

当前问题不是单个选择器写错，而是全项目缺少真正落地的语义字号体系：主题层虽然已有页面标题、数据、卡片标题、分区标题、正文、说明和标签等字号变量，但这些变量与今日页当前形成的实际阅读密度并不一致；产品样式中仍有约 1200 处字号声明直接写成具体 `rpx`，覆盖 44 个产品 WXSS 文件，并形成从 13rpx 到 116rpx 的大量离散值。结果是同一视觉角色在不同页面、公共组件、弹层、空状态和小屏适配中各自生长，后续局部重构又会继续放大差异。

用户需要的不是把所有文字机械缩成同一个尺寸，而是建立稳定的字号层级：同一角色在今日、进度、小队、我的以及子页面中使用同一语义字号；进度页以今日页的正文密度为基准收敛；品牌字、核心数据、计时数字等确有信息层级需要的特殊尺寸继续保留，但必须成为明确、可审计的例外。

## Solution

以今日页当前较轻、较紧凑的阅读密度作为全局校准基准，建立一套覆盖页面标题、分区标题、卡片标题、强调正文、正文、说明、元信息、标签与核心数据的语义字号阶梯，并同步规定对应行高、小屏降级和系统字体放大下的布局要求。

首先收敛进度页：将“教练观察”、观察结论、下一步建议、趋势标题、成长记录、最近完成及其正文映射到统一的语义层级，使它们与今日页的行动分区、AI 提示、任务正文和辅助信息保持接近的视觉大小。随后审计四个主 Tab、公共组件、弹层、加载/空/错状态和所有子页面，把承担文字阅读的硬编码字号迁移到语义令牌。品牌题字、计时器、核心数据和装饰性字形不参加正文等比缩放，但必须使用专用令牌或进入有理由的例外清单。

本次只规范排版尺寸、行高与必要的文本容器适配，不改变业务数据、页面信息架构、交互入口或字体家族方向。完成后，用户在主 Tab 与子页面之间切换时，应感到层级一致、密度接近，不再出现进度页下半段突然整体放大的断层。

## User Stories

1. As an 今日页用户, I want 今日页现有清晰轻量的阅读密度被保留, so that 字体规范化不会把已经舒适的页面做得更拥挤。
2. As an 进度页用户, I want “教练观察”标题与今日页同级分区标题大小接近, so that 页面滚动到该区域时不会突然变重。
3. As an 进度页用户, I want 教练结论使用卡片标题层级而不是接近页面标题的尺寸, so that 结论醒目但不压过当前目标和趋势信息。
4. As an 进度页用户, I want 下一步建议使用强调正文层级, so that 建议易读但不会像第二个大标题。
5. As an 进度页用户, I want 证据、预计用时和操作入口使用统一的说明与元信息字号, so that 卡片内部层级清楚。
6. As an 进度页用户, I want 行动趋势标题与今日页“今日行动”等同级标题保持一致, so that 两个主 Tab 的信息架构具有连续感。
7. As an 进度页用户, I want 成长记录和最近完成的标题、任务名、时间信息遵循同一字号阶梯, so that 页面下半段不会越滚越大。
8. As an 进度页用户, I want 周、月、年切换标签清晰但克制, so that 控件文字不与内容标题争夺注意力。
9. As an 小队页用户, I want 小队标题、行动榜成员名、任务、状态和投入时间与其他页面同角色一致, so that 竞争信息仍然轻量可读。
10. As an 我的页用户, I want 个人资料、目标摘要、成长收藏和设置项使用统一层级, so that 页面不会像来自另一套产品。
11. As an 子页面用户, I want 详情页、设置页、历史页和编辑页延续主 Tab 的字号规范, so that 导航深入后视觉语言不跳变。
12. As an 弹层用户, I want 半屏弹层的标题、字段标签、说明和按钮与页面内同角色一致, so that 弹层不会因字号过大显得沉重。
13. As an 空状态用户, I want 空状态标题、说明和唯一操作入口遵循全局层级, so that 异常状态也保持产品质感。
14. As an 网络失败用户, I want 错误信息和重试按钮清晰可读且不过度放大, so that 我能理解问题并继续操作。
15. As an 加载中的用户, I want 加载文案与正文尺寸一致, so that 状态切换不会引起明显排版跳动。
16. As an 小屏设备用户, I want 文本在窄屏下通过受控降级和换行保持完整, so that 缩小屏幕不会遮挡按钮或截断关键信息。
17. As an 系统字体放大用户, I want 页面允许文本自然换行并保持可操作, so that 可访问性设置不会造成重叠或溢出。
18. As an iPhone 用户, I want 四个主 Tab 的同级文字具有一致视觉大小, so that 不同字体回退不会放大页面差异。
19. As an Android 用户, I want 四个主 Tab 的同级文字具有一致视觉大小, so that 系统字体差异不会让进度页显得异常大。
20. As an 用户, I want 完成数、投入时间、进度百分比等核心数据继续突出, so that 字号统一不会削弱 3 秒内识别关键进度的能力。
21. As an 行动计时用户, I want 计时数字继续使用专门的大号数据层级, so that 执行行动时仍能远距离快速读取时间。
22. As an 用户, I want 品牌题字和山水视觉中的装饰文字继续保持识别度, so that 排版规范化不会抹平品牌特色。
23. As an 开发者, I want 每个文字角色都对应一个语义字号令牌, so that 新页面不需要凭感觉填写尺寸。
24. As an 开发者, I want 字号令牌同时规定建议行高, so that 改小字号后不会残留过大的行距或裁切文本。
25. As an 开发者, I want 四个主 Tab 的同级标题引用同一令牌, so that 后续调整只需修改一处。
26. As an 开发者, I want 公共组件不再依赖页面内随意覆盖字号, so that 同一组件在不同入口中表现稳定。
27. As an 开发者, I want 产品 WXSS 中的硬编码文字字号被自动检查, so that 新改动不会重新制造一大一小。
28. As an 开发者, I want 图标尺寸、品牌字和核心数据显示成为明确例外, so that 契约测试不会逼迫所有视觉元素使用正文令牌。
29. As an 维护者, I want 现有字体家族、字重和数字等宽规则继续生效, so that 本次字号修改不会破坏已完成的字体体系。
30. As an 产品负责人, I want 在常见 iPhone 与 Android 尺寸上对四个主 Tab 做成套截图检查, so that “整体大小差不多”由跨页对比验收而不是只看单页。
31. As an 产品负责人, I want 检查长标题、长任务名和长 AI 建议, so that 统一后真实内容不会溢出或被不必要截断。
32. As an 产品负责人, I want 规划按主题层、进度页、主 Tab、子页面和回归测试分阶段执行, so that 大范围修改可以逐步验证并容易回退。

## Implementation Decisions

### 1. 建立单一语义字号阶梯

- 保留现有字体家族与字重体系，在同一主题层扩展并校准字号令牌，不建立第二套排版变量。
- 建议的常规文字阶梯为：页面标题 40rpx、分区标题 34rpx、卡片标题 28rpx、强调正文 25rpx、正文 22rpx、说明文字 20rpx、元信息 18rpx、标签 16rpx。
- 核心数据默认保持 44rpx；超大品牌字、计时数字和少数数据英雄位使用独立 display/data 令牌，不混入常规文字阶梯。
- 每个字号令牌同时规定默认行高范围：标题约为字号的 1.25～1.35 倍，正文约为 1.45～1.6 倍，标签和单行控件按控件高度垂直居中。
- 现有通用字号变量通过兼容别名过渡到新阶梯，避免一次迁移造成未触及页面失去样式。

### 2. 以视觉角色映射，而不是按数值批量替换

- 页面主标题、分区标题、卡片标题、任务名、正文、说明、标签、按钮、数据分别先判定角色，再替换为令牌。
- 不执行“所有 31rpx 一律改成某值”之类的机械替换；相同旧数值可能分别承担标题、数字或装饰用途。
- 图标通过 `font-size` 控制几何尺寸的场景不视为排版文字，不迁移到正文令牌，但需要在契约扫描中可识别。
- 依赖图片呈现的品牌锁定字不参与 CSS 字号迁移；图片尺寸继续由布局控制。

### 3. 第一优先级修复进度页可见断层

- “教练观察”使用分区标题层级；观察结论使用卡片标题层级；下一步建议使用强调正文层级；证据、完整分析、预计用时和安排任务分别映射到正文、说明或元信息层级。
- 行动趋势、成长记录、最近完成和年度复盘的同级标题统一使用分区或卡片标题令牌，不再保留 35～39rpx 的局部漂移。
- 趋势坐标、图例、范围切换、热力图月份和记录元信息使用说明、元信息或标签令牌。
- 同步调整行高、卡片最小高度、内边距和截断行数，避免字体缩小后出现过多空白，也避免系统字体放大时被固定高度裁切。
- 保留当前目标、累计投入、完成行动数等核心数据的突出程度；数据字号不因正文收敛而被一并缩小。

### 4. 第二优先级统一四个主 Tab 与公共组件

- 以今日页作为基线，逐角色核对今日、进度、小队、我的四个主 Tab 的页面标题、分区标题、卡片标题、正文、说明、标签、按钮和数据。
- 同一语义角色必须引用同一令牌；视觉差异应通过字重、颜色、留白和布局表达，不通过随意放大字号表达。
- 公共 AI 提示、行动列表、目标概览、统计指标、趋势图、榜单行、个人摘要和自定义底部导航一并纳入迁移。
- 四个主 Tab 的加载、空数据、错误和重试状态与正常状态使用同一字号阶梯。

### 5. 第三优先级覆盖子页面、弹层与长文本

- 审计所有产品页面与自建组件，包括历史记录、目标详情、AI 教练、行动执行、资料与设置、邀请和成员管理等低频页面。
- 编辑器、选择器、对话框、半屏弹层的标题、字段标签、输入文本、帮助文字、危险操作和按钮全部映射到语义令牌。
- 法律长文可保留更舒适的长阅读行高，但正文大小必须来自全局正文或专用长文令牌，不继续使用无归属的硬编码值。
- TDesign 内部源码不直接修改；通过主题桥接变量、组件属性或外层类完成一致性调整。

### 6. 建立受控例外清单

- 允许的例外类型仅包括：品牌展示字、计时数字、核心数据英雄位、日历/刻度中的几何数字、图标字体和确有视觉用途的装饰字形。
- 每个例外必须说明角色、适用范围和不能使用常规令牌的原因；禁止以页面名称本身作为豁免理由。
- 响应式媒体查询可以引用对应的小屏令牌或受控降一级，不允许重新写入任意尺寸。
- 系统字体放大不通过整体禁用或强制缩小解决，优先允许换行、增加容器高度和调整相邻布局。

### 7. 分阶段迁移并保持可运行

- 阶段一：校准主题字号与行高令牌，建立兼容别名和例外规则。
- 阶段二：修复进度页“教练观察”起的明显断层，并完成该页全状态验证。
- 阶段三：统一四个主 Tab 和它们直接依赖的公共组件。
- 阶段四：迁移其余子页面、弹层、状态页和自定义底部导航。
- 阶段五：收紧契约测试、运行既有测试与类型检查，并完成跨设备视觉验收。
- 每一阶段都必须可编译、可独立回退，不改动业务事件、数据模型、云调用或路由。

## Testing Decisions

### 什么算好测试

测试只约束用户可观察到的排版契约：同一文字角色使用同一语义字号、关键页面不存在无理由的大字号漂移、常规文字不重新硬编码任意尺寸、例外有明确边界。测试不依赖具体选择器实现细节以外的内部组织，也不对每个像素截图做脆弱断言。

### 唯一自动化测试接缝：全局排版契约测试

扩展现有全局排版契约测试，继续采用项目已有的 Node 断言与源码扫描方式，在一个最高层接缝中覆盖：

- 主题层定义完整的语义字号与行高令牌，并保留字体家族、标题字重、数字字重和数字等宽契约。
- 四个主 Tab 的同角色关键元素引用同一语义令牌。
- 进度页“教练观察”、观察结论、建议、趋势标题、成长记录和最近完成映射到约定层级，不再被测试固定为当前偏大的具体数值。
- 产品页面、组件、样式与自定义底部导航中的常规文本不得新增裸 `rpx` 字号；扫描器排除第三方组件源码，并通过明确的选择器或注释清单识别图标、品牌字、计时器和数据展示例外。
- 响应式规则只能使用语义令牌或批准的小屏令牌，不得在媒体查询里重新引入任意字号。
- 现有进度页视觉契约中固定“教练结论 31rpx”的断言改为语义层级断言，避免测试继续保护已确认的问题。

该接缝复用现有排版契约测试、进度页契约测试和视觉保真测试的先验，不引入新的测试框架。

### 手工视觉验收

- 以同一组真实数据依次截图今日、进度、小队、我的，横向对比页面标题、分区标题、卡片标题、正文、说明、标签和核心数据。
- 至少覆盖常见 iPhone 宽度、窄屏 Android、430px 以上宽屏和系统字体放大场景。
- 进度页重点检查“行动趋势 → 教练观察 → 成长记录 → 最近完成”的连续滚动，确认没有字号断层。
- 覆盖正常数据、无目标、无趋势、加载、错误、长 AI 结论、长任务名和长成员名。
- 验收文字不得遮挡按钮、图标或底部导航；重要内容不能只因迁移令牌而被截断。

### 回归命令

- 运行全局排版契约测试。
- 运行进度页、今日页、小队页和个人页相关的现有契约与视觉保真测试。
- 运行项目现有 TypeScript 类型检查和全部 Node 测试集合。
- 在微信开发者工具中完成编译与 npm 构建检查，确认 TDesign 主题桥接和组件样式正常。

## Out of Scope

- 不改变字体家族方向；继续使用现有品牌衬线、系统无衬线和数字字体体系。
- 不重新设计页面信息架构、卡片结构、底部四 Tab 或核心交互流程。
- 不修改目标、行动、小队、AI 教练、统计或个人资料的数据模型与业务口径。
- 不直接修改 TDesign MiniProgram 的第三方源码。
- 不把所有文本强制成完全相同尺寸；层级差异和核心数据强调仍然保留。
- 不缩小品牌图片、计时器或核心数据来伪造“全局一致”。
- 不在本规格阶段直接实施 WXSS 修改、截图生产或业务代码变更。
- 不引入新的 UI 框架、字体库或动画依赖。

## Further Notes

- 当前全局审计基线为：47 个产品 WXSS 文件中有 44 个包含字号声明，共约 1209 处声明，其中约 1193 处为具体数值，只有少量直接使用现有字号令牌。实现时应重新生成一次基线，因为工作区正在进行其他页面重构，数字可能变化。
- 现有“排版字体体系统一”规格已完成，处理的是字体家族、字重和 Inter 加载；本规格专门处理字号、行高与跨页面层级一致性，不覆盖或回退前一规格。
- 今日页是密度基准，不代表其每一处现有硬编码值都自动正确；实施时仍需将今日页自身映射到语义角色，并清理其中重复覆盖和媒体查询漂移。
- 进度页当前已有测试明确要求教练结论为 31rpx，这与本次用户反馈冲突。实现必须同步更新该断言，否则会出现“视觉问题已修复但旧测试失败”或“为过测试恢复偏大字号”的反向回归。
- 本规格建议的常规字号阶梯是实施起点；若真机对比显示衬线标题视觉体积仍大于无衬线标题，应优先调整对应角色令牌或字重一档，而不是为单个页面重新硬编码。
- 本规格的自动化验收接缝为一个全局排版契约测试；若该接缝与团队预期不符，可在实施前调整规格状态并补充决定，不需要拆成大量逐页面测试。
