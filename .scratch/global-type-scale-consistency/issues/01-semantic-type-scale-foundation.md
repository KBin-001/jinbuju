# 01 — 建立语义字号阶梯与兼容契约

**What to build:** 建立一套以今日页阅读密度为基准的全局语义字号和行高体系，让页面标题、分区标题、卡片标题、强调正文、正文、说明、元信息、标签与核心数据都有唯一且可复用的层级；同时保留现有页面的兼容能力，使后续可以分批迁移而不会让未迁移页面失去样式或导致项目无法编译。

**Blocked by:** None — can start immediately.

**Status:** resolved

- [x] 全局主题提供页面标题 40rpx、分区标题 34rpx、卡片标题 28rpx、强调正文 25rpx、正文 22rpx、说明 20rpx、元信息 18rpx、标签 16rpx和核心数据 44rpx的语义令牌。
- [x] 每个常规字号令牌都有匹配的行高约定，标题、正文、标签和单行控件的垂直节奏清晰且可复用。
- [x] 现有字体家族、标题字重、数字字重与等宽数字规则保持生效，不建立第二套字体体系。
- [x] 旧字号变量通过兼容别名继续工作，尚未迁移的页面在本议题完成后仍能正常编译和显示。
- [x] 品牌展示字、计时数字、核心数据英雄位、日历或刻度数字、图标字体和装饰字形有明确的受控例外规则。
- [x] 响应式字号只能使用语义令牌或批准的小屏降级层级，不鼓励在媒体查询中新增任意尺寸。
- [x] 全局排版契约测试能够验证令牌、行高、兼容别名和例外规则，同时继续验证现有字体体系。
- [x] 项目现有排版契约测试、类型检查和编译不因扩展阶段而回归。

## Answer

在 `miniprogram/styles/theme.wxss` 建立全局语义字号、行高、受控例外和小屏令牌，并保留旧变量兼容别名；新增 `test/type-scale-contract.test.js` 覆盖令牌、字体体系、语义入口和产品 WXSS 扫描。`typography-contract`、字号契约和 TypeScript 检查通过。微信开发者工具与 npm build 脚本不在当前环境，见 [map](../map.md)。
