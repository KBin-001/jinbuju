# 今日行动列表与预计投入时间尺回归修复

Status: ready-for-agent

## Problem Statement

用户进入今日页时，页面仍能统计到 6 个行动，但今日行动卡片没有渲染任何任务；用户打开添加行动弹层后，预计投入区域只剩中央指示器，刻度不可见也无法左右滑动。真实任务没有被删除，但两个核心入口在视觉和交互上均不可用，用户无法确认今天要做什么，也无法设置预计投入。

## Solution

恢复今日行动列表的稳定渲染，并让分组展示失败时自动退回到仍包含全部真实任务的安全分组，任何派生展示异常都不得隐藏任务。时间尺支持 5 到 360 分钟，使用较稀疏的可视刻度和连续滚动换算，在保持 5 分钟选值精度的同时控制渲染节点数量。首尾必须准确选择 5 分钟和 360 分钟。

## User Stories

1. As an 行动用户, I want 今日页始终展示已有行动, so that 我能立即知道今天要做什么。
2. As an 行动用户, I want 页面统计数量和任务列表内容一致, so that 我不会误以为任务被删除。
3. As an 行动用户, I want 今日重点任务显示旗帜图标和说明, so that 我能快速识别最高优先级行动。
4. As an 行动用户, I want 快速推进任务显示闪电图标和说明, so that 我能找到适合立即开始的行动。
5. As an 行动用户, I want 稍后安排任务显示时钟图标和说明, so that 我能理解它们并非丢失而是被安排在后面。
6. As an 行动用户, I want 分组算法异常时仍看到全部任务, so that 展示层故障不会阻断行动入口。
7. As an 行动用户, I want 展开全部任务后看到全部真实任务, so that 收起状态不会永久隐藏行动。
8. As an 行动用户, I want 在添加行动时左右滑动时间尺, so that 我能自然调整预计投入。
9. As an 行动用户, I want 时间尺以 5 分钟为选值精度, so that 我能设置短时行动。
10. As an 行动用户, I want 时间尺最小值准确到达 5 分钟, so that 最短行动不会被错误限制。
11. As an 行动用户, I want 时间尺最大值准确到达 360 分钟, so that 长时行动不会被错误截断。
12. As an 行动用户, I want 30 分钟以内和常用整点刻度清晰可见, so that 我能快速判断当前投入时长。
13. As an 行动用户, I want 滑动时数字和小时说明同步更新, so that 我能确认当前选择。
14. As an 行动用户, I want 松手后时间尺稳定停在最近的 5 分钟值, so that 选值不会漂移或回弹到错误位置。
15. As an 行动用户, I want 时间尺在普通手机和高分辨率手机上都能滑动, so that 设备宽度不会改变业务范围。
16. As an 行动用户, I want 已有任务的执行方式继续正常工作, so that 本次修复不会破坏开始专注或直接完成。
17. As an 行动用户, I want 旧的每次询问数据被安全兼容, so that 历史任务不会因为模式下线而消失。
18. As an 行动用户, I want 页面失败时看到明确内容而不是空白容器, so that 我能判断当前状态并继续操作。

## Implementation Decisions

- 真实行动数组继续作为今日页唯一任务事实源，优先级分组仅作为派生展示结构。
- 页面在派生分组为空但真实行动非空时生成安全回退分组，回退分组必须包含全部传入行动，不修改或写回任务数据。
- 组件空状态只由真实行动数组是否为空决定，不能由分组数组是否为空决定。
- 时间尺业务范围统一为 5 到 360 分钟，选值步长为 5 分钟。
- 时间尺的可视刻度按 15 分钟间隔渲染，滚动位移仍按 5 分钟子步长换算；避免一次创建约 288 个节点。
- 可视刻度从 0 分钟基准开始，到 360 分钟结束；业务选值在换算后钳制到 5 到 360 分钟。
- 常用范围内每 30 分钟显示标签，240 分钟后每 60 分钟显示标签，减少拥挤。
- 滚动首尾事件只负责边界修正，不在普通滚动过程中持续强制回写滚动位置。
- 已下线的执行模式继续在读取时迁移为专注计时，不重新加入前端选择。
- 本次不改变任务数据模型、目标筛选、完成状态、计时会话或云端同步语义。

## Testing Decisions

- 最高测试缝隙是今日页行为契约：给定非空真实行动数组，最终传给组件的展示分组必须非空并完整覆盖行动。
- 第二个测试缝隙是添加行动弹层行为契约：刻度节点数量受控，滚动绑定存在，选值范围为 5 到 360，首尾边界可达。
- 任务分组纯函数继续使用现有优先级单元测试，验证正常分组不丢任务。
- 页面契约测试只断言用户可观察行为和业务范围，不绑定具体 CSS 实现或内部函数行号。
- 服务测试继续验证旧执行模式迁移、行动创建更新和预计投入校验。
- 微信开发者工具恢复后，在常用 iPhone 视口验证任务可见、展开全部、时间尺拖动、5 分钟和 360 分钟边界。

## Out of Scope

- 不重新设计今日页其他卡片、日历、AI 教练或底部导航。
- 不修改任务优先级评分规则和分组容量。
- 不新增执行方式，不恢复“每次询问”。
- 不改造专注计时流程、任务完成逻辑或提醒能力。
- 不清理用户已有任务数据，也不生成演示任务替代真实数据。

## Further Notes

- 当前截图中“查看全部任务（6）”证明任务事实源仍有数据，问题位于派生分组或组件渲染链路。
- 时间尺问题与节点密度直接相关；修复应在保持 5 分钟精度的同时控制可视节点数量。
